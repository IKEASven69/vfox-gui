## 1. 图标（修订版：官方色永远不改，2026-10-01 定稿）

**规则一句话：官方是什么图标、什么颜色，就永远是什么——任何主题、任何底色都不改。**

- **彩色 logo（29 个）去掉垫子直出**：品牌色 glyph 直接放在行背景上
  （GitHub README 的呈现方式），侧栏 18px、详情头 44px。垫子是上一版
  "颜色被影响"观感的根源——灰垫衬得 Ruby 红、Scala 红发闷。
- **官方色纯黑的 8 个**（rust / bun / deno / crystal / java / lua /
  llvm-clang / maven，lum < 0.12）：黑色是官方色、永不改色；但暗色主题
  黑上黑物理不可见，**仅这 8 个在暗色主题保留浅色垫子**——垫子是官方式
  展示面（Rust/Bun 官网自己就是浅底黑 logo），不是改色。浅色主题下无垫
  直出官方黑。近白例外取消：tomcat 浅黄在浅色主题保持官方色，对比弱就弱。
- **新增映射**：nim(#FFE953)、mongod→mongodb 图标。
- 43 个 catalog 最终覆盖：37 官方图标 + 6 字母回落（tinygo / moonbit /
  mingw / ninja / grails / protobuf——simple-icons 官方包确实没有，
  字母是诚实的做法）。

## 2. 全局包扫描单遍提速（现状慢的根因）

现状 `global_packages`（nodejs）：`dir_size(root)` 全树走一遍（含 1.27GB
node_modules），再对每个包 `dir_size` 各走一遍 → 合计 ≈2.3 遍全树，数万文件
在 Windows 上要数秒。

**改法**：单遍递归走运行时根一遍，按路径前缀实时归属——
`node_modules/<top>` 或 `node_modules/@scope/<top>` 下的字节计入该包，
其余计入运行时本体。一遍同时产出：总大小、每包大小、包清单（目录遍历时
顺手读 package.json）。预期 2-3 倍提速；包名列表先行渲染（read_dir 顶层
毫秒级），体积随单遍走树完成后填充。

## 3. 版本间全局包迁移（新功能，场景：切新版本后把旧版全局包搬过来）

场景驱动：24.18 有 1.27GB 全局包，切到 24.21 后目前只能逐个重装（走网络）。

**Rust：`global_migrate(sdk, from_version, to_version, packages, dry_run)`**
- nodejs：从旧 node_modules **复制**包目录到新 node_modules（复制不移动——
  旧版本保持完整、随时可切回），并复制 bin shim 三件套到新运行时根；
  目标已存在同名包 → 跳过并在结果注明（默认不覆盖，可预期）。
- 原生模块检测：包目录内含 `.node` 文件 → 结果标记警告"含原生模块，
  建议在新版本用 npm 重装"（跨 node 版本原生二进制可能不兼容）。
- python：旧解释器 `pip freeze` 导出清单（剔除 pip/setuptools/wheel）
  → 新解释器 `pip install -r`（走网络重装，语义正确——python 包含
  版本相关编译产物，目录复制不可靠）。
- 内置组件排除：npm/corepack/npx 不参与迁移（新版本自带，搬旧的=降级）。
- 双闸门与卸载一致：dry_run 出清单（包数 / 预计新增体积 / 将出现的命令 /
  原生模块警告）→ 确认框 → 执行；迁移完成自动刷新两侧面板与磁盘占用。

**UI**：全局包面板头部加「从其他版本导入」→ 弹出源版本选择（列出其余已装
版本 + 各自包数/体积）→ 勾选包（默认全选、内置组件置灰）→ 迁移。
当前版本面板入口，避免在非活跃版本上误操作方向。
